# 控制台设计笔记

这份笔记记下我们为什么把界面做成现在这样：对照成熟控制台真实被骂的点，说明我们怎么避开；最后列出还要和你商量的取舍。

## 对照别人踩过的坑

### Nacos

- [翻页后再返回会丢页码](https://github.com/alibaba/nacos/issues/11780)：人从详情回列表，期望回到刚才那一页，却被甩回第一页。我们现在条目很少，还没做分页；以后加分页时，页码必须进 URL，刷新和返回都保留当前位置。
- [配置编辑区太小、换行影响阅读](https://github.com/alibaba/nacos/issues/6100)：编辑配置时看不清全文。我们的配置值是短字符串，修改时单独一行输入，核对步骤再整句复述前后值。
- [层级太多、命名空间上下文会丢](https://github.com/alibaba/nacos/issues/7963)、[新控制台 AI 页丢命名空间](https://github.com/alibaba/nacos/issues/15252)：上下文一丢，人以为在改 A，实际改到了 B。我们第一版只有一个平台租户视角，不在导航里堆环境切换；以后加租户选择器时，选择必须进 URL。
- [设计语言分裂、弹窗叠弹窗、缺加载反馈](https://github.com/alibaba/nacos/issues/14652)：我们用同一套 CSS 变量和页面结构；危险操作（改配置）不用弹窗，改用行内「编辑 → 核对 → 确认」；加载失败用明确文案，不给空白页。

### Consul

- [没权限时菜单直接消失](https://github.com/hashicorp/consul/issues/10997)、[ACL 下 KV 菜单被藏](https://github.com/hashicorp/consul/issues/10944)：操作员不知道系统里还有这个功能，只以为「平台没有」。我们的导航**不隐藏**没权限的栏目，置灰并提示「需要权限 xxx」；硬点进去会看到说明缺哪个权限的面板。
- [列表空时分不清「真没有」还是「没权限」](https://github.com/hashicorp/consul/issues/10426)：我们把 403 和空列表分开处理；空列表写「这里还没有内容」，403 写清缺的权限名。

### Spring Boot Admin

- [登录与 CSRF 配置容易踩坑](https://github.com/codecentric/spring-boot-admin/issues/1511)：浏览器端安全配置一错，登录就莫名其妙失败。我们浏览器**不持有**平台账号，只持有随机会话号（httpOnly cookie）；Basic 认证只在 Next.js 服务端转发时使用，登录失败原因用可读文案返回。

### Keycloak

- [Realm 一多，管理台几乎不可用](https://github.com/keycloak/keycloak/issues/20453)、[上千 Realm 时下拉框加载失败](https://github.com/keycloak/keycloak/issues/31956)：下拉一次拉全量会拖死界面。我们第一版没有租户下拉；以后加租户列表时必须分页和搜索，不能一次塞几百条。

### Grafana（常见抱怨，纳入原则）

Grafana 仪表盘常被吐槽「入口深、指标名对非运维不友好」。我们概览页先展示「我是谁、我能做什么」，服务状态用明文 `up`/`down`，不先堆图表。

## 我们已经落实的设计

1. 登录失败就地说明原因（密码错 / 连不上平台），不跳到空白页。
2. 会话是 httpOnly + SameSite=Strict 的随机会话号；账号密码不下发浏览器。
3. 导航栏对没权限的栏目置灰并写明缺什么权限，不隐藏。
4. 配置修改要过「编辑 → 核对前后值 → 确认」；保存后记入审计。
5. 部署页先说清「清单是否已应用到集群」，避免把清单误当成线上实况。
6. 中英文案和三种皮肤（朴素 / 高对比 / 柔和）可切换；默认中文。

## 已定决策（2026-10-05）

1. 没权限的导航：继续置灰并提示缺哪个权限，不隐藏。
2. 改配置：保留「编辑 → 核对前后值 → 确认」三步。
3. 概览页：服务健康、最近审计、未应用的部署提示放在同一页，分区布置。
4. 会话：默认走 Redis（`SESSION_REDIS_URL` / `REDIS_URL`）；未配置时仍用进程内存，方便单机与单元测试。
5. 登录页：也能选语言。
6. 表单页：尽快打开真提交（写入要求相应权限并记入审计）。
