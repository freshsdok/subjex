### 导航与登录路径缺口（本刀针对的路径问题）

- 首页本地回退列表已能到达上述已做页面，但默认画面仍是探测/清单调试区，不像使用入口。
- classpath `uni-app-ui.yaml` 在同意/导出入册后，仍缺少 `nav.profile`、`nav.files`。终端令牌访问 `GET /api/v1/ui-permissions?client=uni-app` 仍会 403（操作员门），壳会回退到本地导航，所以日常可用；但清单一旦对终端开放，资料和文件会从菜单消失。`nav.inbox` 还挂着操作员权限 `inbox.read`，同样可能被置灰。
- 功能页的「去登录」不带返回地址；`goToLogin()` 在 401 时也直接进登录页。登录成功不跳转，使用路径在登录页中断。
- 登录页把绑定/解绑与登录堆在一起，并直接展示接口细节，不适合作为日常入口。
- 没有 tabBar。功能页只有「返回首页」再跳转，本刀不新做底栏（可作为下一刀）。
- 壳目录没有单独的前端单测运行器（仅 `type-check` 与 H5 构建）；路径覆盖主要靠 `EndUserShellAcceptanceTest` 的静态扫描。

### WP7 仍存缺口（本包不在一刀内解决）

- 终端上传没有分片（不复用实体分片会话）。

- 资料只有称呼（`subjectName`），没有头像或邮箱。
- 小程序 appid 仍是运维事项，不在本包交付。

## 本切片已落地（第 1 刀）

1. 首页改为使用入口：用人话说明登录状态和当前组织，并列出已有壳页。不再把 API 根、存活探针或 Manifest 状态放在默认画面。本地导航与清单菜单合并时，会补上清单里缺失的已有页面。
2. 登录页改为日常登录（组织编号、手机号验证码；小程序另提供微信登录）。成功后进入首页，或回到登录前的功能页（仅允许壳内 `/pages/` 路径）。绑定/解绑移到「我的资料」，解绑唯一登录方式时给出人话说明（不再把所有 409 都说成「已提交过问卷」）。
3. Manifest 补上 `nav.profile`、`nav.files`，`nav.inbox` 改为登录即可（不再要 `inbox.read`）。验收：清单菜单覆盖 `pages.json` 中除填写页以外的壳页，填写页仍走 `page` 路由；首页源码含这些入口。

下一刀（若继续打磨壳）：可为常用入口补 tabBar / 底部导航，减少必须先回首页再跳转；不要在那一刀里做厂商适配或结账页。
