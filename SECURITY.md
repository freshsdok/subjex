# Security policy / 安全策略

## Supported versions / 支持的版本

No release has been published. Only the `main` branch (`0.1.0-SNAPSHOT`) receives fixes.
尚未发布任何版本，只有 `main`（`0.1.0-SNAPSHOT`）接受修复。

## Reporting a vulnerability / 报告漏洞

Please do **not** open a public issue for a vulnerability. Use GitHub private vulnerability reporting on this repository (Security → Report a vulnerability). If that option is not available, open an issue titled "security contact request" without any details and a maintainer will reply with a private channel.
请**不要**用公开 issue 报告漏洞。请使用本仓库 GitHub 的私密漏洞报告（Security → Report a vulnerability）。如果该入口不可用，请开一个不含细节、标题为 “security contact request” 的 issue，维护者会回复私下联系方式。

## Deployment boundary / 部署边界

subjex is a pre-release framework skeleton. Treat a build that completes [`docs/release/v0.1.0-alpha.1-checklist.md`](docs/release/v0.1.0-alpha.1-checklist.md) as an **evaluation build per that checklist** — not production-ready, and not for the public internet. Until the checklist (including a PASS backup/restore drill) is green, keep it on a private network only.
subjex 是发布前的框架骨架。完成 [`docs/release/v0.1.0-alpha.1-checklist.md`](docs/release/v0.1.0-alpha.1-checklist.md) 的构建视为**按该清单部署的评估版**——不是生产就绪，也不适合公网。在检查表（含备份恢复 PASS 演练）全部变绿之前，仍只应放在私有网络。

## Known limitations / 已知安全限制

1. **Operator auth prefers opaque Bearer access tokens; HTTP Basic is local/script opt-in (off outside `local`); optional TOTP MFA on password login; optional OIDC SSO.** `POST /api/v1/auth/login` issues a short-lived opaque access token (default 30 min) and a rotating refresh token (default 8 h, stored hashed), or a short-lived `mfaToken` when TOTP is enrolled — completed by `POST /api/v1/auth/mfa/verify`. TOTP secrets are AES-GCM at rest (`PLATFORM_MFA_ENCRYPTION_KEY`); recovery codes are hashed and one-shot. `platform.mfa.required` defaults to false. Optional OIDC RP (`platform.oidc.*`, Authorization Code + PKCE): IdP `sub` must be pre-bound in `operator_idp_link` (deny unlinked; no auto-provision); SSO callback issues the same Bearer pair and **skips local TOTP** (IdP MFA is trusted). Admin bind/unlink: `/api/v1/operators/{login}/idp-link`. APIs accept `Authorization: Bearer <access>`; HTTP Basic is **off by default** (`platform.auth.http-basic-enabled=false`), **on under `local`**, or via `PLATFORM_AUTH_HTTP_BASIC_ENABLED=true` for scripts (Basic does not prompt MFA — break-glass/scripts). Failed password (and MFA verify) attempts are counted per login name (`platform.auth.lockout-max-failures` default 5, `lockout-duration` default PT15M); while locked, `POST /api/v1/auth/login` returns **429** with `reason=login-lockout` (distinct from 401). Terminate TLS in front of every process; the processes themselves do not serve TLS.
   操作员认证优先不透明 Bearer；HTTP Basic 为本地/脚本可选（非 `local` 默认关）；口令登录可选 TOTP MFA；可选 OIDC SSO。登录签发短效访问+轮换刷新，或在已登记 TOTP 时先发短时 `mfaToken` 再校验。TOTP 密钥 AES-GCM（`PLATFORM_MFA_ENCRYPTION_KEY`）；恢复码摘要且一次性。`platform.mfa.required` 默认 false。可选 OIDC 依赖方（`platform.oidc.*`，授权码+PKCE）：IdP `sub` 须预绑定到 `operator_idp_link`（未绑定拒绝、不自动建号）；SSO 回调签发同一 Bearer 且**不二次校验本地 TOTP**（信任 IdP MFA）。管理员绑定/解绑：`/api/v1/operators/{login}/idp-link`。接口接受 Bearer；HTTP Basic **默认关**（`platform.auth.http-basic-enabled=false`），**`local` 打开**，或脚本设 `PLATFORM_AUTH_HTTP_BASIC_ENABLED=true`（Basic 不走 MFA，作逃生/脚本）。按登录名统计口令（及 MFA 校验）失败次数（默认 5 次 / 15 分钟），锁定期间登录返回 **429**（`reason=login-lockout`，与 401 区分）。进程本身不提供 TLS，需在前面终结 TLS。
2. **Console sessions store encrypted access + refresh tokens only (never Basic/password).** The `web/` console keeps only a random session id in the browser (httpOnly, `sameSite=strict`). Memory and Redis store `{ loginName, accessTokenEnc, refreshTokenEnc, accessExpiresAtMillis, expiresAtMillis }` (AES-256-GCM). Redis requires `OPERATOR_SESSION_SECRET` (≥ 32 characters; multi-replica must share it). Without Redis, the same secret is used when set; otherwise a process-ephemeral key encrypts memory sessions. The proxy sends Bearer and silently refreshes once on 401. Logout revokes the refresh family server-side. Password change / disable revokes all token families for that operator.
   控制台会话只存加密的 access/refresh（从不存 Basic/口令）。浏览器只持有随机会话号。内存与 Redis 同为 AES-256-GCM 密文形状。Redis 必填 `OPERATOR_SESSION_SECRET`。代理发 Bearer，401 时静默刷新一次。退出吊销刷新族；改密/禁用吊销该操作员全部令牌族。
3. **Outbox socket transport is a local demo; HMAC + TLS outside `local`.** Default `platform.delivery.transport=socket` keeps `SUBJEX-OUTBOX 2` for laptop/quickstart → sample-consumer: **single address**, body ≤ 4000 bytes, shared HMAC (`OUTBOX_HMAC_SECRET` ≥ 32) — **not** a multi-consumer bus. Operator password is **not** on the wire; timestamp skew ≤ 5 minutes. TLS (PKCS12) is required when `local` is inactive and `platform.delivery.allow-insecure` is false. **Local escape hatch:** `SPRING_PROFILES_ACTIVE=local` allows plaintext TCP with the default HMAC in `application-local.yml`. Optional Kafka adapter (`transport=kafka`, module `subjex-outbox-kafka`) forbids plaintext outside `local` (TLS or SASL required). Mutual TLS and short-lived delivery tokens remain future hardening.
   出箱套接字是本机演示；非 `local` 须 HMAC+TLS。默认 `transport=socket` 保留 `SUBJEX-OUTBOX 2`（**单地址**、正文 ≤4000、共享 HMAC）——**不是**多消费方方案。可选 Kafka（`subjex-outbox-kafka`）在非 local 禁止明文（须 TLS 或 SASL）。双向 TLS 与短时投递令牌仍是后续项。
4. **Gateway client id and `X-Forwarded-For`.** By default `entry-gateway` ignores `X-Forwarded-For` and rate-limits by the TCP remote address. Set `gateway.trusted-proxies` (env `GATEWAY_TRUSTED_PROXIES`, comma-separated IPs/CIDRs) to the proxies that connect **directly** to the gateway; only then is the header read, right to left, skipping trusted hops, and the first untrusted hop is the client. List only proxies you control that append the real peer address — a too-broad range (e.g. `0.0.0.0/0`) brings back header spoofing. Without trusted proxies, every client behind one NAT/proxy shares one bucket. Tomcat's own forwarded-header handling is pinned off (`server.forward-headers-strategy: none`). The header is still forwarded to `platform-app` unchanged; do not use it there for security decisions. Limits are counted per gateway process.
   网关客户端标识与 `X-Forwarded-For`：默认忽略该头，按 TCP 远端地址限流。把**直连**网关的代理写进 `gateway.trusted-proxies`（环境变量 `GATEWAY_TRUSTED_PROXIES`，逗号分隔的 IP/CIDR）后才读该头：从右往左、跳过可信跳，第一个不可信跳即客户端。只填你掌控、且会追加真实来源地址的代理；范围过宽（如 `0.0.0.0/0`）等于重新允许伪造。不配置时，同一 NAT/代理后的客户端共用一个计数。Tomcat 自带的转发头处理已固定关闭（`server.forward-headers-strategy: none`）。该头仍原样转发给 `platform-app`，那边不要据此做安全判断。计数按网关进程各算各的。
5. **Tenants are auto-created on first task submission; operator–tenant grants are required.** `X-Tenant-Id` must be present on tenant-scoped paths (`/tasks/**`, and declaration `tenantScoped` APIs). The operator must also hold a row in `operator_tenant_grant` for that tenant id, or the wildcard `*`. Missing header or missing grant → 403 (fail-closed). Local seed and one-shot bootstrap grant `*` to the provisioned operator so laptop flows keep working. `JdbcTaskMessagePort` still inserts an unknown tenant as `ACTIVE` when a granted submission arrives; explicit admin is `/api/v1/tenants` + console `/tenants`.
   首次提交任务仍会自动建租户；但操作员必须先有租户授权。租户作用域路径要带 `X-Tenant-Id`，且 `operator_tenant_grant` 中须有该租户或通配 `*`；缺头或缺授权 → 403。本地种子与一次性开通给开通的操作员写 `*`。未知租户在获准提交时仍会写成 `ACTIVE`；显式管理见 `/api/v1/tenants` 与控制台 `/tenants`。
6. **Probes stay anonymous on the management port; prometheus is not on the business port.** Each process sets `management.server.port` (platform-app `8089`, entry-gateway `8090`, sample-consumer `8091`). Kubelet liveness/readiness hit that port without auth — restrict to cluster CIDRs (`deploy/k8s/networkpolicy-sample.yaml`). `/actuator/prometheus` is only on the management port. Do not expose management ports via Ingress.
   探针在管理端口匿名；prometheus 不挂业务口。各进程设 `management.server.port`。kubelet 打管理口存活/就绪（无认证）——用集群 CIDR 限制（见 NetworkPolicy 样例）。指标只在管理口。管理口不要经 Ingress 暴露。
7. **Local seed and one-shot bootstrap; runtime operator management APIs exist.** Profile `local` seeds `platform-operator` / `change-me` (with `*` tenant grant); `deploy/compose` enables `local`. Never enable `local` outside a laptop. Outside `local`, provision with the gated bootstrap: `java -jar platform-app.jar --platform.operator.bootstrap=true` plus `PLATFORM_OPERATOR_LOGIN` / `PLATFORM_OPERATOR_PASSWORD` (optional `PLATFORM_OPERATOR_ROLE`); it upserts one operator (role + `*` grant), prints `BOOTSTRAP` warnings, and exits. The flag defaults to **false** — do not leave it on in compose/k8s. Ordinary bootstrap / create **refuse** role `platform.super-admin`. Break-glass uses a separate one-shot: `--platform.operator.super-admin-bootstrap=true` plus `PLATFORM_SUPER_ADMIN_LOGIN` / `PLATFORM_SUPER_ADMIN_PASSWORD` (also off by default; never in compose/k8s defaults); privileges expand at load while `role_permission` stays empty. After bootstrap, use `/api/v1/operators/**` (permission `operator.manage`) to list/create/disable/enable, assign tenant grants, and change another operator's password; any signed-in operator may `POST /api/v1/operators/me/password` with the current password. The `web/` console has an Operators page for self password change and (with `operator.manage`) list/disable/enable. Hand-written SQL still works (`docs/operator-permissions.md`).
   `local` 会写入 `platform-operator` / `change-me`（含 `*` 租户授权），compose 默认启用 `local`。开发机以外不要启用。非 local 用一次性开通（写角色与 `*` 授权后退出，默认关）。普通开通/创建**拒绝** `platform.super-admin`；破窗用独立开关 `super-admin-bootstrap`（同样默认关，勿写入 compose/k8s 默认）。开通后用 `/api/v1/operators/**`（`operator.manage`）做列表/创建/禁用/启用、租户授权、改他人口令；任何人可带当前口令 `POST .../me/password`。控制台有操作员页。手写 SQL 仍可用。
8. **Images are built in CI and scanned (P1); public push optional.** Three Dockerfiles build as non-root uid 10001; Trivy HIGH/CRITICAL gates the alpha tag. Reports: CI artifacts `trivy-*-v0.1.0-alpha.1`. See `docs/release/image-scan.md`.
   镜像在 CI 构建并扫描（P1）；公开推送可选。三 Dockerfile 非 root uid 10001；Trivy 高危门禁 alpha tag。报告见 CI 产物与 `docs/release/image-scan.md`。
